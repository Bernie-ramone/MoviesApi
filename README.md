# MoviesApi

CRUD for `dbo.movies` built with Clean Architecture + CQRS (MediatR), EF Core, FluentValidation and Minimal APIs (.NET 10).

## Layers

```
src/
  Movies.Domain          Entity (Movie), MovieConstraints, IMovieRepository. No dependencies.
  Movies.Application     Commands / Queries + handlers, validators, ValidationBehavior, IUnitOfWork, IMovieQueries.
  Movies.Infrastructure  EF Core DbContext, mapping to dbo.movies, repository (write) and queries (read).
  Movies.Api             Minimal API endpoints, ProblemDetails exception handler, Program.cs.
```

Dependencies only point inward: `Api -> Application/Infrastructure -> Domain`.

CQRS split:
- **Commands** (Create / Update / Delete) go through `IMovieRepository` + `IUnitOfWork` and work on the `Movie` entity.
- **Queries** (GetById / GetMovies) go through `IMovieQueries`, use `AsNoTracking` and project directly to `MovieResponse`.

## Endpoints

| Method | Route               | Result                  |
|--------|---------------------|-------------------------|
| GET    | /api/movies         | 200 paged list          |
| GET    | /api/movies/{id}    | 200 / 404               |
| POST   | /api/movies         | 201 / 400               |
| PUT    | /api/movies/{id}    | 204 / 400 / 404         |
| DELETE | /api/movies/{id}    | 204 / 404               |

OpenAPI document (Development): `/openapi/v1.json`. Sample requests: `src/Movies.Api/Movies.Api.http`.

## Connection string with User Secrets (one-time setup)

User Secrets keeps the connection string **outside the project folder**
(`%APPDATA%\Microsoft\UserSecrets\<id>\secrets.json`), so the password never ends up in source files.
It is loaded automatically when `ASPNETCORE_ENVIRONMENT=Development`.

From `C:\Repos\MoviesApi`:

1. Enable user secrets for the API project (adds a `<UserSecretsId>` to `Movies.Api.csproj`):

   ```
   dotnet user-secrets init --project src/Movies.Api
   ```

2. Store the connection string (replace `<password>`):

   ```
   dotnet user-secrets set "ConnectionStrings:MoviesDb" "Server=192.168.1.74,1433;Database=MoviesDb;User Id=sa;Password=<password>;TrustServerCertificate=True" --project src/Movies.Api
   ```

   - SQL Server uses a **comma** before the port, not a colon.
   - `TrustServerCertificate=True` is needed because the Ubuntu server uses a self-signed certificate.

3. Check it:

   ```
   dotnet user-secrets list --project src/Movies.Api
   ```

To change it later run `set` again; to remove it, `dotnet user-secrets remove "ConnectionStrings:MoviesDb" --project src/Movies.Api`.

## Run

```
dotnet run --project src/Movies.Api --launch-profile http
```

## Notes

- `Id` is generated by the app (`Guid.CreateVersion7()`), `CreatedAtUtc` by the server (`TimeProvider`).
- `AverageRating` / `RatingCount` are read-only in this API (returned in reads, never set by create/update).
- Column lengths live in `MovieConstraints` and are shared by the EF mapping and the validators.
- MediatR is pinned to **12.5.0**, the last version under the Apache 2.0 licence (13+ requires a licence key).
